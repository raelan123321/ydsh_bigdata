# 数仓架构设计文档

项目：云购生活新零售企业——企业级数据仓库与经营分析可视化系统　|　版本：v2.0（第 5 周整合）　|　覆盖：第 2~5 周全部架构演进

## 一、设计目标

构建 ODS → DWD → DWS → ADS 四层数仓，以 DWD 层星型模型为核心，向上支撑预测建模、NL2SQL 问答与双端可视化，向下以 Docker Compose 实现一键部署与可复现运行。

## 二、全系统架构

```
模拟数据源(6 CSV)
      │  Load Data
┌─────▼─────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ ODS 贴源层 │──▶│ DWD 明细层 │──▶│ DWS 汇总层 │──▶│ ADS 应用层 │
└───────────┘   └──────────┘   └──────────┘   └────┬─────┘
  quality_check    clean+dim     6 张聚合表        │ export
                                                   ▼
                        ┌────────────────── MySQL(ydsh_ads)
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
  ECharts 大屏     Superset BI      Streamlit NL2SQL
  (screen-api)    (直连 Hive)      (Hive SQL 闭环)
        ▲                                ▲
        └──── GMV 预测模型 (gmv_forecast) ┘
```

服务编排（docker-compose，7 服务）：mysql:8.0（元数据库）→ hive-metastore → hive-server（自建镜像 w4-hive）→ superset:3.1.0 → clickhouse:24.8（预留 OLAP 扩展）→ screen-api（Flask）→ app（Streamlit）。

## 三、四层架构与命名规范

| 分层 | 定位 | 前缀 | 粒度 | 关键表 |
|---|---|---|---|---|
| ODS 贴源层 | 原样接入，保留脏数据供审计 | ods_ | 最细粒度 | ods_order / ods_order_item / ods_user / ods_product / ods_store / ods_user_behavior |
| DWD 明细层 | 清洗、标准化、维度关联 | dwd_ / dim_ | 明细事实/维度 | dwd_order / dwd_order_item / dwd_order_norm / dim_user / dim_product / dim_store |
| DWS 汇总层 | 主题聚合，可上卷 | dws_ | 天/周/月/品类/门店/渠道 | dws_sales_day / week / month / dws_category_day / dws_store_day / dws_channel_day |
| ADS 应用层 | 面向应用的指标与专题 | ads_ | 应用粒度 | ads_kpi_summary / ads_sales_daily / ads_category_top10 / ads_region / ads_channel / ads_user_value |

## 四、维度建模（星型模型）

- **事实表**：`dwd_order`（订单事务事实：gmv/pay_amount/discount/channel 外键）、`dwd_order_item`（明细事实：qty/单价，挂商品维度）。
- **维度表**：`dim_user`（人口属性）、`dim_product`（品类/价格带）、`dim_store`（门店/省份）。
- **建模依据**：分析主题为「销售行为」，订单是原子业务过程，星型模型使 DWS 聚合只需事实表 + 单维度 join，避免多级雪花 join 的性能损耗。

## 五、技术选型

| 技术 | 版本 | 选型理由 |
|---|---|---|
| Hive | 3.1.3（自建镜像 w4-hive） | 企业数仓标准组件；离线批处理 Tez 引擎 |
| MySQL | 8.0 | metastore 元数据 + ADS 结果服务应用查询 |
| Superset | 3.1.0 | 开源 BI，直连 Hive，REST API 可脚本化建图表 |
| ClickHouse | 24.8 | 预留 OLAP 加速扩展位 |
| Python | 3.10 | 预测(pandas/statsmodels)、NL2SQL、导数、压测 |
| Flask + ECharts | 5.5 | 轻量 JSON 接口 + 大屏渲染 |
| Streamlit | — | 快速搭建问答前端 |
| Docker Compose | — | 7 服务一键编排，healthcheck 启动序 |

## 六、可靠性设计（第 4~5 周联调沉淀）

1. **Hive 幂等初始化**：自建镜像 w4-hive 检测元数据存在则跳过 schematool，容器重启不死循环。
2. **持久化**：Derby 元数据与 warehouse 仓库挂命名卷，容器重建数据不丢。
3. **网络**：HiveServer2 显式绑定 0.0.0.0，healthcheck 就绪后才放行下游。
4. **性能**：dws/ads 按日期分区，分区裁剪实测快 22%；screen-api 接口 HTTP p50 28.5ms。
5. **安全**：MYSQL_ROOT_PASSWORD / HIVE_DB_PASSWORD / SUPERSET_SECRET_KEY 全部 `.env` 注入。

## 七、指标计算链路（口径统一）

GMV 等核心指标在 DWS 单次扫描落小表，ADS 只做轻量组装，保证「一次计算、多处引用」：预测模型读 `dws.dws_sales_day`，大屏读 MySQL `ydsh_ads`，NL2SQL 查 `dws`/`ads` 原表——三处口径同源，联调核对逐位一致（GMV 23,290,536.89 / 9,236 单 / AOV 2,521.71）。
