# 数据质量清洗报告

项目：云购生活新零售企业数据仓库与经营分析　|　版本：v2.0（第 5 周整合）　|　数据基准：2024 全年模拟数据

## 一、报告目的

对源数据中的五类脏数据进行定义、检测、修复与复核，统计修复率，确保进入 DWD 层的数据可信。清洗前数值为 Hive 实跑统计结果，第 5 周联调期间已全量复核确认。

## 二、质量检测框架

按五个维度建立检查 SQL（`sql/quality/quality_check.sql`），覆盖订单、明细、用户、商品、门店、行为六张表：

| 维度 | 检查内容示例 |
|---|---|
| 完整性 | 手机号/商品名空值、主键字段缺失 |
| 唯一性 | user_id、product_id、order_id 重复 |
| 有效性 | 年龄 ≤0 或 ≥120、价格/库存为负、金额异常 |
| 及时性 | 注册时间、订单时间格式不符合规范 |
| 一致性 | 枚举值不规范（性别/订单状态混用编码与中文） |

## 三、五类脏数据：现象、策略与修复率

### 3.1 缺失值

- **现象**：用户年龄缺失 70 条。
- **策略**：可推断字段按业务规则补齐（如按年龄段众数），不可推断字段置默认值并保留审计标记。
- **脚本**：`sql/clean/03_field_merge.sql`（清洗前 70 → 清洗后 0，**修复率 100%**）。

### 3.2 重复数据

- **现象**：用户表 user_id 重复 600 条（完全重复记录）。
- **策略**：按主键去重，保留首条有效记录。
- **脚本**：`sql/clean/02_outlier_format.sql`（清洗前 600 → 清洗后 0，**修复率 100%**）。

### 3.3 异常值

- **现象**：金额异常 622 条（负金额 310 条 + 超大金额 312 条）。
- **策略**：负金额按业务规则修正（退货冲正/取绝对值标记），超大金额结合品类价格带上限截断。
- **脚本**：`sql/clean/02_outlier_format.sql`（清洗前 622 → 清洗后 0，**修复率 100%**）。

### 3.4 枚举不规范

- **现象**：枚举字段混用编码与中文，共 3,050 条（gender 606 条 + 订单状态 2,444 条，如 `cancelled` 与「已取消」并存、状态出现裸数字 `2/3/4`）。
- **策略**：建立标准枚举映射表统一归一（`sql/clean/01_enum_mapping.sql`），DWD 层仅保留标准枚举。
- **修复率 100%**（清洗前 3,050 → 清洗后 0）。

### 3.5 格式问题

- **现象**：日期时间格式混杂（`yyyy/MM/dd HH:mm` 与 `yyyy-MM-dd HH:mm:ss` 并存）、字段分隔符不一致。
- **策略**：统一转换为 ISO 标准 `yyyy-MM-dd HH:mm:ss`，为分区字段（dt）提供规范基础。
- **脚本**：`sql/clean/02_outlier_format.sql`（**修复率 100%**）。

## 五、清洗对数仓的影响

- ODS 订单 15,600 单经无效单剔除（待支付/已取消等 600 单）后，DWD 有效订单 **15,000 单**，订单明细 35,695 条。
- 第 5 周联调复核：DWD→DWS→ADS 逐层行数与 KPI（GMV 23,290,536.89 元 / 9,236 单 / AOV 2,521.71 元）逻辑自洽，清洗质量满足验收标准。

## 六、结论与验证方式

五类脏数据经枚举标准化、异常值处理、格式统一、去重补齐后修复率均为 100%，且可由 `sql/quality/quality_check.sql` 在任意环境复跑验证。修复口径在《需求文档》指标体系中留痕，实现「可检测、可修复、可追溯」。
