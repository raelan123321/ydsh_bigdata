## 一、系统架构

```
                    ┌──────────────────────────── Docker Compose 网络 ────────────────────────────┐
                    │                                                                             │
  浏览器 ──8088──▶  │  superset(BI)  ──hive://hive-server:10000──▶  hive-server ◀──hive-metastore │
  浏览器 ──8080──▶  │  screen-api(Flask大屏) ──app/data JSON──▶  ECharts 大屏(index.html)          │
  浏览器 ──8501──▶  │  app(Streamlit问答) ──NL2SQL──▶ hive-server                                  │
  浏览器 ──8123──▶  │  clickhouse(OLAP 预留)                                                       │
                    │        全部服务共享 mysql:3306 元数据 / 结果库                                 │
                    └─────────────────────────────────────────────────────────────────────────────┘
```

| 服务 | 镜像 | 端口 | 职责 |
|------|------|------|------|
| mysql | mysql:8.0 | 3306 | Hive metastore 元数据库 / ADS 结果库 |
| hive-metastore | w4-hive（基于 apache/hive:3.1.3 自建） | 9083 | 元数据服务 |
| hive-server | w4-hive | 10000/10002 | HiveServer2（JDBC/pyhive 接入） |
| superset | apache/superset:3.1.0 + pyhive | 8088 | BI 仪表板 |
| clickhouse | clickhouse/clickhouse-server:24.8 | 8123/9000 | OLAP 引擎（预留扩展） |
| screen-api | w4-app（python:3.10-slim） | 8080 | 大屏 JSON 数据接口 + 静态页面 |
| app | w4-app | 8501 | Streamlit 智能问答（NL2SQL 闭环） |

### Hive 镜像的两处改动（hive/ 目录）

原生 `apache/hive:3.1.3` 有两个直接影响可用性的问题，自建镜像 `w4-hive` 做了修正：

| 问题 | 现象 | 处理 |
|------|------|------|
| entrypoint 无条件执行 `schematool -initSchema` | 元数据已存在时抛 `FUNCTION 'NUCLEUS_ASCII' already exists` 并 exit 1，容器重启即挂（表现为 compose 反复 Error dependency failed） | `hive/entrypoint-idempotent.sh`：仅当库目录不存在时初始化，否则跳过 |
| 元数据/仓库目录在容器可写层 | `docker compose down` 后容器重建，表定义与数据全部丢失，需重跑全部 SQL | 挂命名卷 `hive_metastore`、`hive_warehouse`、`hive_warehouse_legacy` |

另：`hive/conf/hive-site.xml` 在**保留镜像默认项**（`hive.execution.engine=tez`、`tez.local.mode=true`、scratch 目录等）的基础上追加动态分区、Derby 库路径、HS2 绑定 `0.0.0.0` 等配置。注意不能只写自选项覆盖整个文件——丢掉 Tez 配置会让引擎退回 MR，并报 `org/apache/hadoop/metrics/Updater` 缺失。

启动顺序依赖（depends_on + healthcheck）：
mysql(healthy) → hive-metastore → hive-server(beeline 健康检查) → {superset, app}
mysql(healthy) → screen-api

## 二、一键部署

```bash
# 0. 准备密钥（.env 不入库，见《API 配置指南》）
cp .env.example .env      # 按需修改数据库密码与 LLM_API_KEY

# 1. 一键启动全部服务（首次会自动构建 w4-app / superset 镜像）
docker compose up -d

# 2. 查看各服务状态（hive-server 健康检查约需 2~3 分钟）
docker compose ps

# 3. Superset 初始化（管理员 + 元数据库）
docker exec superset superset db upgrade
docker exec superset superset fab create-admin --username admin \
    --firstname Admin --lastname User --email admin@example.com --password admin
docker exec superset superset init

# 4. 自动创建数据源/数据集/图表/仪表板（可选，也可 UI 手工操作）
pip install requests && python python/superset_setup.py
```

验证通过标准：`docker compose ps` 中全部服务 Up（或 healthy）；浏览器分别访问
- Superset 仪表板：http://localhost:8088（admin/admin）
- ECharts 大屏：http://localhost:8080
- Streamlit 问答：http://localhost:8501
- ClickHouse：http://localhost:8123（返回 Ok）

## 三、数据大屏（子任务 2）

- 设计稿 1920×1080，`scale = min(内宽/1920, 内高/1080)` 整体缩放，窗口任意尺寸不错位
- 图表：月度 GMV 双轴折线、品类 Top10 渐变柱状、渠道玫瑰饼图、区域地图（ECharts map + 阿里 DataV GeoJSON）、时段×品类热力图、GMV-订单量散点
- 数据接口：`GET /api/all` 一次返回 7 组 JSON（KPI/趋势/品类/渠道/区域/热力/散点），数据由 `app/gen_data.py` 从第 3 周 KPI 结果与模拟数据预生成

## 四、Streamlit 智能问答（子任务 3）

- 提问 → `NL2SQL.generate`（LLM 或规则兜底）→ `guard` 只放行 SELECT 并自动补 limit → pyhive 执行 → DataFrame 展示 → 按结果形状自动推荐折线/柱状图（ECharts 本地内联渲染）
- 侧栏含示例问题、历史对话、清空按钮；异常时给出中文错误提示
- 无 LLM_API_KEY 时自动降级为规则兜底，闭环不中断

## 五、查询优化与压测（子任务 5）

- 分区裁剪：ADS/明细查询一律带 `where order_date between ...`，避免全表扫描
- 存储：ADS 层 `STORED AS ORC`；高基数 key（user_id）加盐打散避免倾斜
- 压测脚本：`python/press_test.py`
  - Hive 对比：带分区 vs 全表扫描各 3 轮×3 并发，输出 p50/p95/max
  - HTTP 压测：并发 10 请求 `GET /api/all`，输出延迟分布与 QPS
  - 结果写入 `output/week4/press_result.json`（实测数值见《压力测试记录》）

## 六、数据持久化与重建

| 卷 | 挂载点 | 内容 |
|---|---|---|
| mysql_data | /var/lib/mysql | MySQL 数据（含 ydsh_ads 结果库） |
| hive_metastore | /opt/hive/metastore_db | Hive 元数据库（Derby） |
| hive_warehouse | /opt/hive/data/warehouse | 数仓数据文件（dwd/dws/ads） |
| hive_warehouse_legacy | /opt/hive/warehouse | ODS 与部分历史表数据文件 |
| superset_data | /app/superset.db | Superset 元数据（连接、图表、Dashboard） |
| clickhouse_data | /var/lib/clickhouse | ClickHouse 数据 |

- `docker compose down`（不加 `-v`）后重新 `up`：数据与仪表板全部保留，Hive 直接跳过初始化启动。
- `docker compose down -v`：卷被删除，需按 `sql/` 顺序重跑全链（ODS→clean→dwd→dws→ads），本仓提供了可复用的重灌脚本 `output/week4/restore4.sh`。
- 重灌注意：若曾用 `rm -rf` 清空 warehouse 目录，必须同时 `drop database ... cascade` 重建库，否则会出现「表已存在」导致后续建表段整段跳过、维表为空。
- 生产环境建议：元数据库换 MySQL/PostgreSQL 并启用独立 metastore，仓库目录指向 HDFS/对象存储，避免单机 Derby 的容量与并发限制。

## 七、常见问题排查

| 现象 | 原因 | 处理 |
|------|------|------|
| superset 起不来 | hive-server 未通过健康检查 | `docker compose ps` 等 healthy；首次 Tez 初始化约 3 分钟 |
| Superset 连不上 Hive | 驱动缺失/连接串错 | 镜像已内置 pyhive；连接串必须写 `hive://hive@hive-server:10000/default`（容器名，不是 localhost） |
| Streamlit 报 Hive 连接失败 | hive-server 未就绪 | 等待 healthy 后刷新页面 |
| 构建时 apt/pip 超时 | 容器内直连国外源不通 | Dockerfile 已换国内源（阿里云 apt + 清华 pip） |
| sasl 编译失败 | 缺 g++/libsasl2-dev | 已在镜像中预装 |
| 大屏地图空白 | GeoJSON 未加载 | screen-api 提供 `/china.json`，确认 8080 可访问 |
